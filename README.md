# Маршрут поступления (рабочее название)

AI-сервис персонального маршрута поступления в вузы Казахстана.
Кейс 02 — LOCUS Startup Hackathon 2026, код кейса `LOCUSCASE2`.

## Задача

Абитуриенту нужен не ещё один список вузов, а понятный маршрут: куда поступать, почему это
подходит именно ему и что делать дальше. Информация о поступлении разрознена, а типовые
AI-чаты дают общие советы без персонализации и плана действий.

## Решение

Короткая анкета → диагностика профиля → минимум 3 рекомендованных вуза с объяснением
«почему подходит» (rule-based скоринг) → сравнение вариантов → персональный roadmap с
шагами и дедлайнами → один ближайший следующий шаг с отметкой прогресса. Рекомендации и
roadmap пересчитываются при изменении ключевых ответов (интересы, бюджет, балл ЕНТ, город).

## Сегмент

Ученики 10–11 классов и выпускники школ, поступающие в бакалавриат в Казахстане.

## Стек

- Next.js 16 (App Router), React 18
- Tailwind CSS
- Состояние профиля — React Context + `localStorage` на клиенте
- Серверные API-роуты Next.js (`app/api/ai/*`) — единственная серверная часть, нужна только
  для AI-слоя; без неё всё приложение осталось бы полностью статичным (это и было изначально,
  см. «Ограничения» про GitHub Pages)
- Gemini API (`gemini-2.5-flash`) — персонализация текста поверх rule-based логики
- Деплой — Vercel (нужен из-за серверных роутов; auto-deploy при пуше в `main`)

## Архитектура

```
app/
  page.js                  — Вход
  profile/page.js          — Анкета
  diagnosis/page.js        — Диагностика
  recommendations/page.js  — Рекомендации
  compare/page.js          — Сравнение
  roadmap/page.js          — Roadmap
  next-step/page.js        — Следующий шаг
  api/ai/diagnosis/route.js — серверный роут: AI-текст диагностики
  api/ai/explain/route.js   — серверный роут: AI-объяснения рекомендаций
lib/
  ProfileContext.js        — состояние профиля (localStorage)
  data/universities.js     — датасет вузов (частично проверенные данные, частично демо)
  recommend.js             — rule-based логика рекомендаций
  roadmap.js               — генерация шагов roadmap
  constants.js             — справочники (интересы, города, бюджет, шаги)
  ai/gemini.js             — обёртка над Gemini API + проверка на «выдуманные» числа
  ai/useAiText.js          — client-хук: debounce, кэш, таймаут, fallback на шаблон
components/
  StepHeader.js             — индикатор шага пути (где я нахожусь)
```

## Запуск

```bash
npm install
cp .env.example .env.local   # вписать GEMINI_API_KEY (бесплатно: aistudio.google.com/apikey)
npm run dev
```

Открыть http://localhost:3000. Без ключа приложение тоже работает — AI-тексты просто не
подгружаются, и везде показывается шаблонный текст (fallback), сценарий не ломается.

## Тестовый сценарий

1. Открыть главный экран → «Начать за 2 минуты».
2. Заполнить анкету (класс, интересы, балл ЕНТ, бюджет, город) → «Показать диагностику».
3. Посмотреть диагностику → «Смотреть рекомендации».
4. Выбрать 2 вуза кнопкой «Сравнить» → «Сравнить выбранные».
5. Перейти к roadmap, отметить прогресс по шагам.
6. Открыть «Что делать дальше?» — убедиться, что показан именно первый невыполненный шаг.
7. Вернуться в анкету, изменить бюджет или интересы — убедиться, что рекомендации и roadmap
   заметно меняются.

## Данные и источники

Датасет вузов в `lib/data/universities.js` помечен `isDemoData: true` — проходные баллы и
стоимость обучения указаны приблизительно. **Перед финальной сдачей необходимо сверить
актуальные цифры с официальными сайтами вузов и Univer.kz**, либо оставить явную пометку
«демо-данные» на экране рекомендаций (уже реализовано).

## AI / API

Модель: **Gemini 2.5 Flash** (Google AI Studio API), вызывается только с сервера (API-ключ
никогда не попадает в браузер).

Что делает rule-based логика, а что — AI:

- **Rule-based** (`lib/recommend.js`, `lib/roadmap.js`) считает сам подбор вузов, баллы
  соответствия и причины «почему подходит» — это не меняется, это остаётся детерминированным
  и проверяемым.
- **AI** (`app/api/ai/diagnosis`, `app/api/ai/explain`) только переписывает уже посчитанный
  результат живым, персональным текстом — не решает, какой вуз рекомендовать, и не добавляет
  новых фактов.

Защита от галлюцинаций: ответ модели проверяется функцией `numbersAreGrounded` — если в тексте
появилось число, которого не было в исходных данных (профиль + rule-based причины), ответ
отбрасывается и показывается шаблон. То же самое происходит при таймауте или ошибке API —
`useAiText` откатывается на шаблонный текст, сценарий никогда не ломается из-за AI.

## Ограничения

- Скоринг вузов — rule-based правило, AI его не заменяет, только переписывает текст (см. «AI / API»).
- Датасет ограничен ~14 вузами (10 Казахстан + 4 демо-варианта за рубежом) для демонстрации.
- Даты приёмной кампании — демонстрационные, требуют проверки перед финальной сдачей.
- Деплой — Vercel, а не GitHub Pages: серверные AI-роуты не могут работать на чисто
  статическом хостинге, поэтому от статического экспорта отказались в пользу Vercel
  (бесплатный тариф Hobby, auto-deploy из GitHub).
